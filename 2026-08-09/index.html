Cloudflare Precursor、セッション全体の行動からbotとAIエージェントを検出

セキュリティAIエージェントOpen Beta
出典: Cloudflare Blog / Cloudflare Docs / InfoQ（2026-08-08）

CloudflareはPrecursorをオープンベータで提供した。マウス移動、キー入力の間隔、反応時間などをクライアント側で継続的に観測し、単一リクエストではなく訪問セッション全体の一貫性からbotやAIエージェントを判定する。CAPTCHAや指紋だけを模倣する自動化には運用コストを上げられる一方、正規利用者への割り込みを減らせる。Security Analyticsにもセッション単位の表示が加わる。実装側は、検出精度だけでなく、収集信号の最小化、同意、保持期間、誤判定時の救済経路まで設計対象にする必要がある。

実務への含意: 導入評価では、bot遮断率に加えて正規ユーザーの誤検知率とプライバシー影響を計測する。セッション識別子や行動データを既存のログ保持方針へ無条件に混ぜず、用途・保存期間・アクセス権を明示する。

GitHub、npmとActionsの供給網防御を「任意機能」から安全な既定値へ

Supply ChainGitHub Actionsnpm
出典: GitHub Blog / InfoQ（2026-08-08）

GitHubは3〜7月に導入したnpmとActionsの防御策を整理した。高影響npmアカウントはメール変更や2FA復旧後に72時間読み取り専用となり、Actionsでは信頼できないforkコードのcheckoutやキャッシュ書き込みを既定で制限する。Trusted Publishing、段階公開、外向き通信の可視化も組み合わせ、侵入・権限昇格・認証情報流出・拡散の各段階を分断する設計だ。利用者は既定値だけに依存せず、長期シークレット削除とworkflow権限の棚卸しを優先すべきである。npm v12ではinstall scriptも既定で無効化される。

実務への含意: CIの永続トークンをOIDCベースの短命認証へ置き換え、fork由来トリガーの権限、キャッシュ共有、外向き通信先を監査する。72時間の待機だけでは、失効ドメインや侵害済みrelease workflowの問題は解決しない。

_for-sale DNSレコード仕様が更新、稼働中ドメインの売却意思を機械判読

DNSRFC 10023相互運用
出典: Website Spec（2026-08-08更新） / RFC 10023

Website SpecはRFC 10023に基づく _for-sale DNSレコードの解説を更新した。所有者は _for-sale.example.com のTXTに v=FORSALE1 と、連絡先URI、説明、価格など最大1個の属性を置き、通常のWebやメールを止めずに売却意思を表せる。WHOISやRDAPが登録状態を示すのに対し、この規約は「登録済みだが購入可能」を仲介業者や探索サービスへ伝える。採用時はTXTの真正性をDNSSECと所有確認で補い、表示前に内容を検証する必要がある。ブラウザー表示を置き換えるドメインパーキングとは用途が異なる。

実務への含意: ドメイン探索サービスはTXTだけで所有権や価格を確定せず、DNSSEC、HTTPS上の案内先、追加の本人確認を組み合わせる。運営側は売却終了時のレコード削除を資産管理手順へ入れる。
