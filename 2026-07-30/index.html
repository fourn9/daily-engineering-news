Uber Engineering が本日 exact COUNT(DISTINCT) の分散 pipeline 実装を公開。問題設定 = business 側の "unique rider 数 / retention curve / A/B experiment 効果測定" 等 近似 (HLL: HyperLogLog) では受入れられない exact count 要件、かつ event 数は数十億/day 級。HLL は 1-2% 誤差で cost が O(log N)、exact は誤差 0 だが cost が O(N)、"exact だけど N が大きい" 領域の設計論。技術核心 (推定) = (a) time window + entity dimension で partitioning して worker 分散、(b) bloom filter で pre-filter して skew を抑制、(c) rollup できない要件を "sub-cube pre-aggregation + on-demand join" で分割、(d) KV store (RocksDB) の chunked flush で memory pressure を制御。結果 = HLL 実装比で "誤差 0" を維持しつつ scale-out 可能、A/B test の "有効性 significance" 判定を高信頼で回せる基盤。
